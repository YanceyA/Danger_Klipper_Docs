CoreXY precise homing

Sensorless homing finds the axis limit a little earlier or later on every home. This PR adds an optional second step. It measures the corner with one motor, then sets the home position on a whole number of motor electrical cycles, so the same physical spot is called home on every G28.

The idea

A stepper motor repeats the same pattern of coil currents every four full steps. That repeat is one electrical cycle. With a 1.8° motor and rotation_distance: 40 it comes round every 0.8 mm of belt. The points where a cycle starts are fixed to the rotor and the belt, so they work as a ruler built into the machine.

StallGuard cannot find the limit to a hundredth of a millimetre. It can easily tell which 0.8 mm tick the limit is next to. So the code measures the distance to the limit in cycles, subtracts a calibrated origin, rounds to a whole number, and builds the home position from that whole number only. The rounding throws the stall noise away.

Motors and gantry

On a CoreXY, neither motor owns an axis. Motor A is stepper_x and its belt position is X + Y. Motor B is stepper_y and its belt position is X − Y. Turn one motor alone and the head runs on a 45° diagonal. The whole feature leans on that: one motor, on its own, can reach the X limit by turning one way and the Y limit by turning the other.

The electrical cycle and the phase

The TMC driver keeps a microstep counter (MSCNT) that says where the motor is inside its current cycle. Klipper reads it and stores, per motor, an offset called moff so that (mcu_position + moff) % phases is the motor's phase at any step count. Phase 0 is the start of a cycle. The PR uses that value to stand both motors on phase 0 before it measures anything.

Calibration

  
COREXY_HOMING_CALIBRATE runs the same measurement several times (5 by default) and stores where the corner falls inside a cycle. Each sample starts from a different grid point, set by CAL_GRID: whole cycles of A and B away from the first. If the machine is consistent, the whole-number part of each result changes and the fraction stays put.

  
The fractions are averaged on a circle, because 0.49 and −0.49 are neighbours, not opposites. If any sample is more than 0.15 cycle from the mean the command fails with “not repeatable” and the old origin is kept. On success the origin is used at once and is written to the config file by SAVE_CONFIG.

The corner Klipper reports after a snap is the grid point, not the wall. The wall sits origin cycles away from it. That is why the docs warn that the home position can move by up to about half a cycle per motor after a new calibration.






  
When the snap runs

  
The precise step needs X and Y to both hold a position that came from a real home. unsnapped_axes tracks that. An axis is added when its home finishes, and removed when it is about to be homed again, when SET_KINEMATIC_POSITION forces its position, or when its homed state is cleared. When the set holds both 0 and 1, it is emptied and the snap runs once.

    4. 
        
  4. SAVE_CONFIG. From now on every home of both X and Y is snapped.
    5. 
        
  5. Check positions that must be exact, such as a probe dock. The home position can have moved by up to about half a cycle per motor.

Questions a reviewer may ask

  
These follow from reading the code. None is a bug report; they are the points to have an answer for.

  
    
    
  • Is hold_current checked? No. The docs require that neither driver sets it, but nothing in corexy.py enforces it.
    • 
    
  • What about rails with more than one motor? Only the first stepper of each rail is phase aligned and counted (rail.get_steppers()[0], line 191), and the driver is looked up by the rail name. A second motor such as stepper_x1 is not checked.
    • 
    
  • Which speed do the non-probing moves use? his[0].retract_speed, the homing_retract_speed of stepper_x, for the park, the nudge and every return (line 187).
    • 
    
  • What survives a restart after a rejected home? Only the in-memory origin is cleared (line 253). After RESTART the saved value is loaded again, so the next home is checked against it once more until a new calibration is saved.
    • 
    
  • How much longer is a home? At least four extra probe moves (two per limit), at most ten, each about offset mm of head travel on each axis and back.
    • 
    
  • What does a slipped belt do? By the arithmetic, not a test: one 2 mm belt tooth is 2.5 cycles of 0.8 mm, so a one-tooth slip moves that motor's fraction by half a cycle and the home is rejected until recalibrated. Lost motor steps come in whole cycles and leave the fraction unchanged.
    • 
    
  • Where does the head end up? About corexy_precise_homing_offset mm from both endstops, not at the regular retract distance.
